# 2026-10-16 — Tiger Style wave 1: first buildable, tested tree

Facts established during the solutions Tiger Style remediation wave 1
(tracker: ~/workspace/solutions-tiger-audit/ on Pax's VM):

- `discord/go.mod` opened with `#` header comments, which are not
  valid go.mod syntax — the module could not even be parsed by the
  Go toolchain. Header is now `//` comments.
- `internal/config`, `internal/model`, and `internal/bus` were
  referenced by `cmd/bot`, `cmd/llmworker`, `internal/llm`, and
  `internal/auth` but did not exist. They are now implemented,
  following the `discord/layout` blueprint's types and signatures,
  with Tiger Style deviations recorded here: fallible operations
  return errors (`config.Load`, `auth.LoadTLS`, `bus.ConnectJetStream`,
  `bus.Subscribe`) and the original `Must*` entry points wrap them
  with the same fatal behavior; `model.Kind.String()` returns
  "unknown" for out-of-range values instead of panicking (the
  blueprint indexed an array with the Kind); `NewDiscordMessage`
  is nil-safe.
- `internal/llm` and the root bot now bound their HTTP work
  (prompt/response byte caps, client timeout, non-200 is an error)
  and check errors the fragments ignored (marshal, request build,
  body close, publish/send results — golangci-lint errcheck clean).
- Root bot command parsing is now exact: `!ask <prompt>` only;
  `!askfoo` and prompt-less `!ask` no longer query rose.
- First test suite: 23 tests across 6 packages, validation and
  adversarial cases (nil/empty/oversized inputs, malformed and
  oversized responses, unreachable servers, invalid TLS material).
  Gates on primo 2026-10-16: `go build ./...` ok, `go vet` 0,
  `gofmt -l` clean, `golangci-lint run` 0 issues,
  `go test -race -count=1 ./...` all pass. govulncheck is not
  installed on primo — that gate was not run.
- `go mod tidy` dropped the unused `jackc/pgx` requirement and
  raised `google/uuid` / `nats-io/nats.go` to the versions the
  remaining dependencies require; `go.sum` is now committed.
- Still skeleton, unchanged: `cmd/email` and `cmd/smsgw` are
  TODO placeholder mains; there is no live Discord/NATS/rose
  integration test (all tests are hermetic).
